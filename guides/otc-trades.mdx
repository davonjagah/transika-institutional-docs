Transika supports bidirectional trades between USDT or USDC and GHS.

| Direction | You provide | You receive |
| --- | --- | --- |
| `crypto_to_fiat` | USDT or USDC | GHS to a beneficiary, or managed tGHS |
| `fiat_to_crypto` | GHS | USDT or USDC to your wallet |

## Requirements

- Approved merchant KYB/KYC.
- The `otc` feature entitlement.
- `api:read` for reads and `api:write` for mutations.
- Test keys use `/sandbox/v1`; live keys use `/v1`.

## Create a trade

```bash
curl -X POST "https://sbx-institutional.tran-sika.com/sandbox/v1/otc/trades" \
  -H "Authorization: Bearer $TRANSIKA_TEST_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "direction": "crypto_to_fiat",
    "settleMode": "fiat",
    "amountIn": 1000,
    "assetIn": "USDC",
    "network": "base",
    "sendingWallet": "0x1111111111111111111111111111111111111111",
    "beneficiaryId": "BENEFICIARY_ID"
  }'
```

Provide either `amountIn` or `amountOut`. The quote supplies the corresponding amount, exchange rate, expiry, and funding instructions.

## Trade lifecycle

```text
draft → quoted → accepted → funding_submitted → funded → settling → settled
```

| Status | Meaning |
| --- | --- |
| `draft` | Waiting for a quote. |
| `quoted` | Quote and funding instructions are ready. |
| `accepted` | You accepted the quote before expiry. |
| `funding_submitted` | Your funding proof was submitted. |
| `funded` | Transika confirmed funding. |
| `settling` | Settlement is processing. |
| `settled` | Settlement completed. |
| `expired` | Quote expired before acceptance. |
| `cancelled` | Trade was cancelled. |
| `rejected` | Funding could not be confirmed. |

Read the trade or consume OTC webhooks until it reaches a terminal status.

## Settlement paths

### Fiat settlement

For `crypto_to_fiat` with `settleMode: "fiat"`, Transika sends GHS to the selected beneficiary.

### Managed tGHS settlement

For `crypto_to_fiat` with `settleMode: "managed_tghs"`, the quoted GHS amount becomes available in your managed tGHS balance. No beneficiary is required.

### Crypto settlement

For `fiat_to_crypto`, Transika sends the selected stablecoin to `receiveWallet`.

## Test the full flow

In Test, `simulate-ops` advances a non-terminal trade without moving funds.

```bash
curl -X POST \
  "https://sbx-institutional.tran-sika.com/sandbox/v1/otc/trades/$TRADE_ID/simulate-ops" \
  -H "Authorization: Bearer $TRANSIKA_TEST_API_KEY"
```

<Warning>
  Trade creation does not currently accept an idempotency key. If a request times out, check the trade list before retrying to avoid a duplicate.
</Warning>
