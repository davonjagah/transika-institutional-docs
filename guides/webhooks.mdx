Webhooks deliver **tGHS payout lifecycle** events to your HTTPS endpoint. Endpoint management requires approved KYB/KYC, the `api_access` feature, and `api:read` or `api:write`.

OTC desk activity runs in the Transika dashboard and is notified by email and in-app alerts. It is not delivered over merchant HTTP webhooks.

## Events currently delivered

| Event | When |
| --- | --- |
| `webhook.test` | You call the test endpoint |
| `tghs.payout.created` | Payout / redemption accepted |
| `tghs.payout.burn_submitted` | Burn submitted (real chain in Live; simulated in Test) |
| `tghs.payout.burn_confirmed` | Burn confirmed |
| `tghs.payout.payout_pending` | Ghana disbursement started |
| `tghs.payout.completed` | Beneficiary payout succeeded |
| `tghs.payout.burn_failed` | Burn failed |
| `tghs.payout.payout_failed` | Ghana payout failed after burn |

Subscribe with `tghs.payout.*`, an exact event name, or `*`. An empty or omitted `events` array receives all events that are emitted to merchant HTTP webhooks. Test and Live use the **same event names and redemption-shaped `data.payout`**; create separate endpoints (or use environment) for each mode.

## Create an endpoint

```bash
curl -X POST "$TRANSIKA_API_URL/v1/sandbox/webhooks/endpoints" \
  -H "Authorization: Bearer $TRANSIKA_TEST_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://hooks.merchant.example/transika/payouts",
    "description": "tGHS payout lifecycle",
    "environment": "test",
    "events": ["tghs.payout.*", "webhook.test"]
  }'
```

Example created endpoint (`signingSecret` returned once):

```json
{
  "status": "success",
  "message": "Webhook endpoint created",
  "data": {
    "id": "ea503d42-a37e-4667-8ae9-9b006a5fd021",
    "url": "https://hooks.merchant.example/transika/payouts",
    "description": "tGHS payout lifecycle",
    "enabled": true,
    "environment": "test",
    "events": ["tghs.payout.*", "webhook.test"],
    "secretPrefix": "whsec__fl-2n",
    "signingSecret": "whsec_REPLACE_WITH_ONE_TIME_SECRET",
    "createdAt": "2026-08-08T16:37:17.870Z"
  }
}
```

Copy `signingSecret` immediately and store it in your secret manager.

<Warning>
The full signing secret is visible only in the create response and immediately after rotation. Endpoint listings return only `secretPrefix`. If you lose the secret, rotate it.
</Warning>

Endpoints are environment-specific. A Test endpoint receives Test payout events; a Live endpoint receives Live redemption events.

Headers include:

```text
Content-Type: application/json
X-Transika-Event: tghs.payout.completed
X-Transika-Delivery: 9a8b7c6d-5e4f-3a2b-1c0d-9e8f7a6b5c4d
X-Transika-Timestamp: 1786190400
X-Transika-Signature: t=1786190400,v1=HEX_HMAC
```

Use the event `id` or `X-Transika-Delivery` value for idempotency. Your handler should return any `2xx` response only after it has durably accepted the event.

## Verify signatures

Transika computes:

```text
signedPayload = timestamp + "." + rawBody
signature = HMAC-SHA256(signingSecret, signedPayload)
```

The timestamp is the `t` value in `X-Transika-Signature`. The body must be the exact raw request bytes decoded as UTF-8. Do not parse and re-serialize JSON before verification.

```javascript
import crypto from "node:crypto";
import express from "express";

const app = express();

app.post(
  "/webhooks/transika",
  express.raw({ type: "application/json" }),
  (request, response) => {
    const rawBody = request.body.toString("utf8");
    const signatureHeader = request.get("X-Transika-Signature") ?? "";
    const parts = Object.fromEntries(
      signatureHeader.split(",").map((part) => part.split("=", 2)),
    );

    const timestamp = parts.t;
    const received = parts.v1;
    if (!timestamp || !received) return response.sendStatus(400);

    const expected = crypto
      .createHmac("sha256", process.env.TRANSIKA_WEBHOOK_SECRET)
      .update(`${timestamp}.${rawBody}`, "utf8")
      .digest("hex");

    const valid =
      /^[a-f0-9]{64}$/i.test(received) &&
      crypto.timingSafeEqual(
        Buffer.from(received, "hex"),
        Buffer.from(expected, "hex"),
      );

    if (!valid) return response.sendStatus(401);

    const event = JSON.parse(rawBody);
    // Persist and process event.id idempotently.
    return response.sendStatus(204);
  },
);
```

Also reject stale timestamps using a tolerance appropriate for your system clock and delivery queue. Compare `X-Transika-Timestamp` with the signed `t` value before processing.

## Endpoint security requirements

Endpoint URLs must:

- Use HTTPS.
- Resolve publicly; private, loopback, link-local, multicast, reserved, `.local`, and localhost addresses are blocked.
- Omit embedded URL credentials.

Transika rejects unsafe destinations and does not follow redirects. Your endpoint must still authenticate every signature and apply normal request limits.

## Retries

A delivery succeeds on any `2xx` response. Timeouts, network errors, and non-`2xx` responses are retried for a limited period. Delivery is at least once, so duplicate events are possible and your handler must process event IDs idempotently.

## Test, rotate, and revoke

```bash
# Queue webhook.test
curl -X POST \
  "$TRANSIKA_API_URL/v1/sandbox/webhooks/endpoints/$ENDPOINT_ID/test" \
  -H "Authorization: Bearer $TRANSIKA_TEST_API_KEY"

# Rotate the signing secret
curl -X POST \
  "$TRANSIKA_API_URL/v1/sandbox/webhooks/endpoints/$ENDPOINT_ID/rotate-secret" \
  -H "Authorization: Bearer $TRANSIKA_TEST_API_KEY"

# Revoke the endpoint
curl -X DELETE \
  "$TRANSIKA_API_URL/v1/sandbox/webhooks/endpoints/$ENDPOINT_ID" \
  -H "Authorization: Bearer $TRANSIKA_TEST_API_KEY"
```

Rotation replaces the secret immediately. Update your receiver with the returned `signingSecret` before relying on later deliveries.
