Transika's merchant API accepts secret API keys as bearer tokens.

## Send a bearer token

Include your key in the `Authorization` header on every API request:

```http
Authorization: Bearer txk_test_REPLACE_ME
```

```bash
curl "https://sbx-institutional.tran-sika.com/v1/sandbox/transactions" \
  --header "Authorization: Bearer ${TRANSIKA_API_KEY}" \
  --header "Accept: application/json"
```

<Warning>
  Never place a secret key in browser code, mobile application bundles, logs, screenshots, support tickets, or source control. Call Transika from a trusted server.
</Warning>

## Key environments

The prefix identifies the key's environment and must match the request path.

| Key prefix | Environment | Request prefix |
| --- | --- | --- |
| `txk_test_` | Sandbox | `/v1/sandbox` |
| `txk_live_` | Live | `/v1` |

A mismatched key and path returns `400`. The request path, not an environment header, selects the environment.

## Get an API key

Create and manage API keys in the authenticated merchant dashboard. The `api_access` entitlement is required.

When creating a key, choose its environment, grant the minimum required scope, and configure the source IP addresses that may use it. Store the secret immediately because it is displayed only once.

<Tip>
  Give each integration and deployment its own key. This limits the impact of rotation and makes usage easier to audit.
</Tip>

## Authentication failures

| Status | Typical cause |
| --- | --- |
| `400` | The key prefix does not match the live or sandbox path. |
| `401` | The bearer token is missing, malformed, invalid, expired, or revoked. |
| `403` | The source IP is not whitelisted, the key lacks a required scope, KYB is not approved, or a feature is not entitled. |

See [Response envelopes and errors](/getting-started/responses-and-errors) for the error body format.
